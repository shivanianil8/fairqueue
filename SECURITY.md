# FAIRQUEUE Security Architecture & RBAC Specifications
> **Authentication, Authorization, Auditing, and Access Control Standards**

---

## 1. Authentication Architecture

FAIRQUEUE employs industry-standard cryptographic primitives built directly on the native Node.js `crypto` subsystem to avoid brittle native C++ bindings and ensure cross-platform reproducibility.

### Password Storage: PBKDF2 with SHA-512
- **Algorithm**: Password-Based Key Derivation Function 2 (PBKDF2)
- **Digest**: SHA-512
- **Iterations**: 10,000 iterations
- **Salt**: 16 cryptographically secure random bytes generated per-user via `crypto.randomBytes(16)`
- **Storage Format**: `salt:hash` (e.g. `a4b7...e9:7c3f...d1`)
- **Verification**: Evaluated using `crypto.timingSafeEqual` to eliminate timing side-channel attacks:
  ```javascript
  const computedHash = crypto.pbkdf2Sync(password, salt, 10000, 64, 'sha512').toString('hex');
  return crypto.timingSafeEqual(Buffer.from(originalHash, 'hex'), Buffer.from(computedHash, 'hex'));
  ```

### Session Token: HMAC-SHA256 JWT
- **Header**: `{"alg": "HS256", "typ": "JWT"}` (Base64URL-encoded)
- **Payload**: Encodes `userId`, `email`, `name`, `role`, `organizationId`, and `exp` timestamp.
- **Signature**: Generated via `crypto.createHmac('sha256', JWT_SECRET)` over `header.payload`.
- **Token Expiry**: Default duration is 24 hours (`86,400,000 ms`).

## 4. Controlled Manual Override Security Model

Manual overrides bypass the Prolog Horn clause deductive ranking. To prevent abuse and guarantee compliance:

1. **Role Enforcement**: Only users with role `ADMIN` or `QUEUE_MANAGER` are cryptographically permitted to invoke `/api/queues/:queueId/entries/:entryId/override`.
2. **Mandatory Justification Reason**: The API rejects any override request where `overrideReason` is missing or contains only whitespace.
3. **Immutability of Audit Record**: Every override logs:
   - Identity of the manager authorizing the override (`overriddenBy`).
   - Exact UTC timestamp (`overriddenAt`).
   - Previous priority deduced by Prolog vs. newly assigned manual priority.
   - Exact text justification reason.
4. **Permanent UI Flagging**: Overridden entries display a distinct amber badge (`[OVERRIDDEN]`) and are retained in operational compliance metrics.

## 5. Input Validation & API Protection

- **Payload Sanitization**: Numeric waiting times are bounded to non-negative integers (`waitingTime >= 0`).
- **Enumeration Whitelisting**: Attributes (`urgency`, `appointmentStatus`, `specialRequirement`, `priority`) must match strict whitelisted sets before being passed into Prolog fact unification.
- **Prolog Injection Prevention**: Dynamic Prolog facts generated by `prologService.js` sanitize visitor identifiers and names to prevent code injection into the Prolog interpreter:
  ```javascript
  const safeId = String(p.personId).replace(/[^a-zA-Z0-9_-]/g, '');
  const safeName = String(p.name).replace(/'/g, "\\'");
  ```
